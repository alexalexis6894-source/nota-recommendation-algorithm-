# Архитектура НОТЫ

## Рекомендации (главное для разбора)

**Сценарий.** Человек собирает группу из своих ароматов (до 30), ставит их по приоритету: сверху то, что нравится
больше. НОТА подбирает из каталога 36 ароматов в двух режимах:
- `close` «Похожие на мои»: те же главные ноты, что в группе;
- `new` «Новое в моём вкусе»: тот же характер, но другие ноты, чего у человека ещё нет.

Из подборки человек заказывает пробники-отливанты (до 15 в наборе), наличие и цены в `backend/data/offers.json`.

**API.** `GET /api/v1/groups/{id}/recommendations?mode=close|new&limit=36`, один запрос на 36 позиций,
клиент показывает по 12. Ответ:

```json
{
  "group": {"id": "…", "name": "…", "pids": [25967, 31861]},
  "stock_connected": true,
  "items": [{
    "pid": 9828, "name": "Aventus", "brand": "Creed", "mode": "close",
    "accords": ["древесный", "фруктовый", "…"],
    "reputation": {"rating": 4.3, "rating_count": 21000},
    "matches": ["ананас", "берёза"],
    "differences": {"added": [{"label": "…"}], "missing": [{"label": "…"}]},
    "similar_to": [{"pid": 31861, "name": "Sauvage", "brand": "Dior"}],
    "offer": {"volume": "5 мл", "price": 900}
  }]
}
```

Значения выше для примера, поля взяты из того, что читает `frontend/groups.js`.

Человеку объясняем выбор словами: «совпадает с вашей группой», «чем отличается», «по характеру близок к …».
Поэтому любой алгоритм должен уметь выдать эти объяснения.

**Код.** `backend/app/groups.py` – подбор и группы, `backend/app/similarity.py` и `backend/data/similarity.pkl` (8 МБ) –
близость ароматов, `backend/app/notes_ru.json` – русские названия нот, `backend/app/orders.py` – заказы пробников.
Во фронте: `frontend/groups.js` (экран групп и подборки), `frontend/app.js` (`profileOf`, `recommend` –
упрощённый демо-подбор на 14 выдуманных ароматах, без сервера).

**Данные каталога.** 140 255 ароматов с Фрагрантики, `catalog.json` (43 МБ) и то же в `catalog.sqlite`
(таблица `cards(i, pid, card)`, в `card` JSON). Поля карточки:

| поле | что это |
|---|---|
| `pid`, `name`, `brand` | id Фрагрантики, название, бренд |
| `rating`, `votes` | средняя оценка (есть у 121 тыс.) и число голосов |
| `accord_weights` | аккорды с силой 0–100 по голосам: `citrus:100|fresh spicy:47|…` |
| `note_weights` | ноты с весом 0–100: `orange:100|bergamot:28|…`, верх, сердце и база идут подряд без меток уровня |

Чего в каталоге нет: уровней пирамиды, пола, года, описаний, стойкости и шлейфа, «похожие» и «напоминает» по голосам.
Это компактная выжимка, исходный датасет у владельца. `catalog-index.pkl` (14 МБ) – индекс поиска по названию.
`offers.json` – 5450 ароматов, которые можно заказать пробником: `{"pid": {"ml": 5.0, "price": 900}}`.

**Пример слабого места.** По Eau Sauvage (Dior) режим close выдаёт Eau Sauvage Extreme того же бренда и клон
«Eau de Sauvegy», а Eau Sauvage Extreme попадает и в режим new.

## Распознавание по фото (контекст)

1. **iPhone, `frontend/recognition.js`.** Человек снимает флаконы (до 10 кадров за серию) или выбирает фото.
   Клиент пережимает кадр в JPEG (качество 0.86 → 0.78 → 0.7, до 12 МБ) и шлёт
   `POST /api/v1/recognition` с `{request_id, image_base64, media_type, filename}`.
2. **Хостинг, `frontend/api/index.php`.** PHP-шлюз запускает `backend/gateway.py` отдельным процессом на каждый
   запрос (CGI), не больше 4 одновременно, таймаут 100 с. Снимок встаёт в очередь в `data/photos.sqlite`.
3. **Mac владельца, `mac-worker/`.** Обработчик опрашивает хостинг каждые 2–10 с (`/v1/phone/claim`, `/v1/phone/heartbeat`),
   забирает снимок, прогоняет через модель распознавания и отдаёт результат. До 3 снимков параллельно.
   Если Mac выключен, распознавание недоступно.
4. **Хостинг, `backend/app/recognition.py` и `search.py`.** Ответ модели сопоставляется с каталогом,
   к каждому флакону добавляются кандидаты из каталога.
5. **iPhone.** Клиент опрашивает `GET /api/v1/phone/result/{id}` раз в 1,5 с, ждёт до 310 с,
   показывает флаконы с уверенностью и вариантами, человек подтверждает и добавляет в коллекцию.

## Формат ответа распознавания

```json
{
  "id": "…", "status": "complete",
  "warnings": ["…"],
  "bottles": [{
    "id": 0,
    "brand": "Chanel", "name": "Bleu de Chanel", "concentration": "Eau de Parfum",
    "visible_text": "BLEU DE CHANEL EAU DE PARFUM",
    "confidence": "high | medium | low",
    "reason": "почему модель так решила",
    "bbox": [x, y, w, h],
    "alternatives": [{"brand": "…", "name": "…"}],
    "catalog_status": "candidates | not_found | unknown",
    "matches": [{"pid": 25967, "name": "Bleu de Chanel Eau de Parfum", "brand": "Chanel"}]
  }]
}
```

Первые семь полей даёт модель, `matches` и `catalog_status` добавляет поиск по каталогу (до 8 кандидатов).
Если уверенность `high` и кандидат один, клиент сразу отмечает его.

## Ограничения продакшена

- Общий хостинг Рег.ру, PHP 8.3 и Python из venv, без GPU, без постоянно работающих процессов.
- Python стартует заново на каждый запрос (~0,7 с процессора на старт). Лимит тарифа по процессору около 19 тыс. с в сутки,
  поэтому частые запросы (опрос очереди, аналитика) отвечает PHP без Python.
- Запрос живёт до 100 с, тело до 12 МБ для фото.
- Подбор считается в процессе Python на каждый запрос: всё тяжёлое надо считать заранее и держать в компактных файлах.
- Распознавание сейчас завязано на Mac владельца, это узкое место по доступности.
